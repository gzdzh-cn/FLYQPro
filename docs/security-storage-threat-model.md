# FlyQPro 存储与身份威胁模型

状态：第一阶段审计基线。传输稳定版不以数据库加密为阻断项；迁移验证前不得删除明文数据库或旧备份。

## 保护目标

- 设备私钥和未来的数据加密主密钥不得写入普通配置文件、日志或导出包明文。
- 消息正文、引用/转发正文、附件本地路径和个人敏感字段属于静态数据保护范围。
- 传输恢复范围、会话 generation 和设备身份必须防止旧记录或旧 ACK 被重新接受。

## 信任边界

- 局域网、发现广播和未认证 TCP/UDP 输入均不可信。
- TLS 使用自签名设备证书；`InsecureSkipVerify` 只用于关闭公共 CA 验证，每条外连仍必须在 `VerifyConnection` 中同时校验期望设备 ID、设备公钥和证书指纹，任何缺失字段均按未信任处理。
- 设备公钥变化映射为 `DEVICE_KEY_CHANGED`；同公钥的证书指纹变化映射为 `CERTIFICATE_CHANGED`。两者都要求用户重新确认，不自动更新信任记录。
- macOS Keychain、Windows Credential Manager 和 Android Keystore 是设备密钥及数据主密钥的唯一持久来源。

## 加密迁移设计

- 使用 AES-256-GCM；每个字段使用随机 96-bit nonce，AAD 为 `表名|主键|字段名|密钥版本`。
- 加密数据写入旁表，读取顺序为加密值优先、明文回退；写入阶段双写，每批最多迁移 500 行并记录迁移游标和错误。
- 迁移中断后从最后一个已提交批次继续。备份恢复和抽样解密验证完成前保留明文字段。
- 回滚使用迁移前 SQLite 快照；快照必须通过 SQLite backup API 生成，不直接复制活动 WAL 数据库文件。
- 用户导出包必须使用用户口令经 Argon2id 派生的密钥加密，并包含 schema 版本、密钥版本和文件 SHA-256 清单。

## 发布审计项

- 日志、诊断事件和崩溃信息不得包含私钥、数据密钥、完整消息正文或绝对附件路径。
- 验证错误密钥、损坏密文、迁移中断、旧数据库读取、备份恢复和回滚；任一消息或附件记录丢失均阻断启用加密。
